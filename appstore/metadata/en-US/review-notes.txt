Launchpane is a local macOS utility for developers, power users, and Mac
support professionals who need to understand and safely manage background
services that otherwise require launchctl commands and hidden plist folders.
It solves the problem of diagnosing startup behavior, service state, and
launchd configuration from one focused interface.

1. Access and main flow

Launch the app directly; there is no account, sign-in, registration, demo
credential, subscription, or network setup. The inventory loads from the
review Mac. Use the search field and source dropdown to inspect User Agents,
Home Agents, System Agents, System Daemons, and Login Items. Select a row to
inspect state, configuration, schedule, and available logs. User Agents can
be enabled, disabled, started, stopped, restarted, tested, edited, created,
and removed. Login Items support only Enable and Disable because they are
owned by their parent app. System Agents and System Daemons are displayed for
context and remain read-only.

To exercise the write flow safely, choose New Agent and create a temporary
agent using `/usr/bin/true` as the executable, leave Run at Login disabled,
save it, select it, then remove it. The app writes only to the user's
`~/Library/LaunchAgents/` directory. No sample file or account is required.

3. External services

Launchpane does not use external services to deliver its core functionality.
It reads local launchd state, local plist files, local log files, and
ServiceManagement login-item metadata through macOS APIs and commands. It
does not use analytics, advertising, authentication, payment processing,
cloud storage, AI services, or remote data providers. All service and plist
information remains on the Mac. The sandboxed Tauri/WebKit runtime requires
local network client and server entitlements to start its embedded web
process; Launchpane does not contact an external endpoint or expose a network
service.

4. Regional behavior and regulated content

The app has no regional feature or content differences. It behaves
consistently in all territories. It is not a regulated-industry service and
does not include protected third-party material or user-generated content.

5. Sandbox and ownership boundaries

The Mac App Store build is sandboxed with narrowly scoped temporary
exceptions for the standard launchd locations. It writes only user-owned
agents in `~/Library/LaunchAgents/`; system agents and daemons are read-only.
Temporary sandbox exception details and assessment steps are documented in
`appstore/sandbox-exceptions.md`.

6. Edition limits and project reference (candidate not yet submitted)

The updated Store-feature build keeps applicable unavailable controls visible
but disabled with an explicit "Unavailable in the Mac App Store edition"

are read-only. Login-helper lifecycle controls are disabled; Enable/Disable
remain the only permitted changes.

An optional "Project documentation and source on GitHub" link opens
https://github.com/webmaxru/Launchpane in the system browser. It supplies project
documentation and source; the repository also describes separate standalone
distribution. Launchpane does not download, install, update, or unlock external
code. No purchase, license, or external payment flow is provided by the link.
The Store edition works independently and does not require another edition.
