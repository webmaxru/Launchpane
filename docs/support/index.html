Support

Launchpane is maintained as an open-source project.

Get help

Search existing reports or open a new issue in the GitHub issue tracker. Include your macOS version, Launchpane version, edition (standalone or Mac App Store), the affected service type, and steps to reproduce the problem.

Which edition should I download?

For service management, we recommend the standalone release. It supports lifecycle controls, enable/disable, personal-agent removal, and an explicit administrator window. Official releases from v1.2.2 are Developer ID signed and Apple notarized. Signing verifies the developer and detects changes; notarization checks for known malware. Keep Gatekeeper enabled and do not bypass malware, damaged-app, or unverified-developer warnings. These checks are not a guarantee of safety or a substitute for App Store review. Read Apple's download security guidance.

The Mac App Store edition is available for inspection and personal LaunchAgent plist editing. App Store sandbox and privilege restrictions mean it cannot load, run, stop, restart, enable, disable, or remove services, or open an administrator window. Compare downloads.

Why is the Store inventory empty after reopening?

Choose inventory folders using Choose folders…. Only selected roots are scanned, and folder grants last until quit. Select them again after reopening, including log folders when needed. Saving a personal plist only writes the file; it does not activate or reload the service. Shared services and login helpers remain read-only.

Permissions

User agents live in ~/Library/LaunchAgents. System agents and daemons are protected by macOS and are shown as read-only unless an explicitly authorized operation is available.

Logs

Launchpane displays the stdout and stderr paths configured by each launch agent. The app does not upload these logs.
